If you go back and forth only occasionally, meaning you pull data at specific times, that's a batch approach, which we've seen in previous lessons. But if there's constant traffic, meaning data is flowing continuously, what was that, folks? That's the streaming scenario. Databricks offers you different tools for both situations. For batch, you set up simpler and more controlled connections, while on the streaming side, more dynamic and continuously running structures come into play. What matters now is how data flows, and how you manage it. Viewed differently, the standard connector is an approach, not just a tool. It answers the question, how do I connect to the data? That's the answer. Sometimes you connect to a cloud storage, sometimes to a data streaming system, and sometimes to files that are constantly being updated. But here's the common point, folks. Databricks accesses the data, reads it, and the whole process happens according to the standard connector logic. So, we've seen how Databricks connects to data in the cloud environment. In other words, how the bridge between the data and the processing engine is formed. There, we focus more on the question, how do we establish the connection? That was the main question we focused on. Now, I'm going to take this process one step further, and look for an answer to this question. Can we make this connection easier? This is where the managed connector comes into play. In data engineering, one of the most time-consuming and error-prone steps is establishing a connection to the data source. Connection details, security settings, access permissions, authentication processes, each of these requires a separate configuration. It's possible to set up this process manually. However, repeating the same steps over and over again each time is both inefficient and risky. Managed connector is an approach that simplifies this process. You can think of it like a ready-made connection panel. Instead of setting up a connection from scratch, you use a predefined structure. You just fill in the required fields. The system takes care of the remaining technical details for you. This way, you save time and establish a more secure and standardized connection. At this point, Databricks offers some connectors within itself. Look, friends, for example, Salesforce ServiceNow. See, you can connect directly to systems like SQL Server or Google Analytics from here. There are ready-made integrations available. These connectors provide quick access to frequently used data sources, especially in enterprise projects. However, in the real world, data sources are not limited to just a few systems. Companies collect data from many different platforms. At this point, Databricks works in integration with third-party solutions like Fivetran. Friends, Fivetran is a managed ETL service that can connect to hundreds of different data sources. So, by using this integration within Databricks, you can access a much broader data ecosystem. Here's the important point. The managed connector is not a standalone tool, but rather a facilitation layer. In other words, while you set up the connection yourself with the standard connector, with the managed connector, most of this process is managed automatically on your behalf. This provides a major advantage, especially when it comes to rapid development, prototyping, and building operational systems. Also, friends, this approach brings standardization to data engineering. Instead of everyone connecting in different ways, things move forward through a specific and reliable structure. This not only increases team alignment, but also makes the systems more sustainable. In summary, the standard connector answers the question, how do we establish the connection? While the managed connector answers the question, how can we do this faster, easier, and more securely?
